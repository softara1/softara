ما استُلهم من الفكرة (إعادة هندسة لا نسخ)

  • التعرف التلقائي على المنصة من الرابط واختيار طريقة التضمين الصحيحة — أعدنا بناءه بمحلل parseSource() أضخم ويغطي قوائم يوتيوب (PL/UU/FL/RD/OL) وروابط shorts وdai.ly وgeo.dailymotion وvkvideo وأرشيف الإنترنت وm3u8.
  • واجهة شبكة أغلفة بدل قائمة مواضيع — طوّرناها إلى شبكة 16/10 مع شارات (جودة/تصنيف/قيد التشغيل/كتالوج) وحالة hover تفاعلية.
  • قوائم تشغيل المسلسلات كاملة في عنصر واحد — طبّقناها بذكاء أكبر: زر «القائمة الكاملة (تتحدث تلقائيًا)» يركّب قائمة رفع القناة الرسمية (UU…) داخل المشغل الرسمي فتظهر الحلقات الجديدة تلقائيًا دون أي تحديث يدوي.
  • DailyMotion API المجاني لعناوين وصور الفيديوهات (بدون مفتاح)، ومسارات التضمين الرسمية geo.dailymotion.com وvkvideo.ru/video_ext.php وok.ru/videoembed.
  • ترقيم الحلقات من العناوين ومتابعة/مفضلة محلية — بنيناها مع بحث أعمق يشمل عناوين الحلقات نفسها.

المشاكل التي اكتشفناها في أكواد مسرووور وتجنّبناها

① حجم ضخم يعطل السرعة 563KB جافاسكربت + jQuery يُحمَّلان على صفحات المنتدى — منصتنا: ~75KB إجمالي (CSS+JS+بيانات) بلا jQuery.
② مصدر «المشغل داخل المشغل» كوده يحول الروابط والإطارات معًا داخل الموضوع — لو احتوى المنشور رابطًا وiframe يظهر مشغلان. منصتنا: منطقة تشغيل واحدة (#stmStage) يُفكَّك كل محتواها قبل أي تشغيل جديد — التداخل بنيويًا مستحيل.
③ كشط مواضيع عند كل زيارة يجلب صورة غلاف كل موضوع بطلب شبكة منفصل (بطء + حساسية لأي تغيير من أحلى منتدى) — منصتنا: بيانات منسّقة مسبقًا ومفحوصة، صفر كشط وقت العرض.
④ منصات معلنة كمدعومة لكنها ممنوعة التضمين تحققنا فعليًا: sendvid وmp4plus يرسلان X-Frame-Options (لن يعملا داخل أي iframe). منصتنا: مصفوفة دعم صادقة مبنية على اختبار رؤوس HTTP حقيقي + بطاقة «شاهده على منصته» لما يمنع التضمين.
⑤ صور غلاف مُخمَّنة بمسارات مكسورة (مثل مسارات uqload الثابتة) — منصتنا: صور فقط من مصادر رسمية (i.ytimg.com، archive.org، dmcdn) مع بديل SVG تلقائي عند الفشل.
⑥ اعتماد على بروكسيات CORS عامة لجلب قوائم IPTV — اختبرنا 12 بروكسيًا عامًا وكلها ميتة/مقيدة 2025. منصتنا: تحديث القنوات عبر قوائم الرفع الرسمية المضمنة (لا يحتاج بروكسي إطلاقًا) + محاولة هادئة عبر وسائط إن توفرت.
⑦ فيديوهات محدودة العمر تظهر شاشة سوداء في كوده (لا يفحصها) — نحن نتحقق بـ oEmbed وقت البناء ونستبعد أي معرف يرجع 401 (6 فيديوهات استُبعدت فعليًا أثناء البحث).

4حل مشكلة المشغل المزدوج نهائيًا

المبدأ: منطقة تشغيل واحدة فقط #stmStage داخل إطار المشغل #stmShell. أي تشغيل جديد يمر بالدورة:

mount(item)
 1. teardown()  ← إزالة الـiframe/الـvideo من الشجرة (الصوت يتوقف فورًا)
                 + hls.destroy() + إلغاء blob URLs + تصفير المؤقتات
 2. بناء المشغل الجديد حسب نوع المصدر داخل المنطقة الفارغة نفسها
 3. شارات المصدر (YouTube / DailyMotion / MP4 / HLS…) في الشريط العلوي
نتيجة الاختبار الفعلي تنفيذ سلسلة تبديلات سريعة: MP4 (يعمل) ← DailyMotion ← يوتيوب ← HLS — القياس بعد كل خطوة: عنصر وسائط واحد بالضبط (1 if / 0 vid أو 0 if / 1 vid) — لا طبقات ولا صوت خفي ولا نافذتان.

يوتيوب عمدًا بلا IFrame API (iframe رسمي فقط بـ youtube-nocookie) — أخف، وأثبت، وواجهة يوتيوب الرسمية الكاملة (جودة/ترجمة/سرعة) داخل المنطقة نفسها دون أي تعارض مع شروط المنصة.

قواعد الحقوق المطبقة

  • لا روابط مقرصنة ولا تجاوز اشتراكات — أعمال لا تتوفر مجانًا رسميًا (Prison Break، كونان، الكابتن ماجد العربي) أُدرجت كتالوج تعريفي بمقطعها الرسمي وروابط المنصات الرسمية، موسومة «كتالوج رسمي» بوضوح.
  • كل معرف فيديو تحقق عبر oEmbed — استُبعدت 6 معرفات ردت 401 (مقيدة العمر/خاصة).
  • ملاحظة المصدر ظاهرة في ورقة كل عمل (قناة رسمية / ملكية عامة / مقطع رسمي).

7قناة «أفلام تركية مدبلجة» والتحديث التلقائي

الحل المعتمد (رسمي 100%) قناة المستخدم حُلّت إلى UCGjgAGxGWZXWLTHTlTVZXaw. مكتبتها تعرض أحدث 15 فيديو (لقطات RSS حقيقية بعناوينها وصورها) + زر «القائمة الكاملة (تتحدث تلقائيًا)» يركّب قائمة رفع القناة الرسمية UUGjgAGxGWZXWLTHTlTVZXaw داخل مشغل يوتيوب الرسمي — كل فيديو جديد يُنشر في القناة يظهر فورًا دون أي تعديل يدوي، وهذا ضمن واجهات يوتيوب الرسمية وشروطها تمامًا.
  • عند زيارة الصفحة تحاول المنصة بهدوء جلب RSS مباشر عبر وسائط CORS إن توفرت (تحديث البطاقات أيضًا) — إن لم تتوفر، تبقى اللقطات + القائمة الكاملة الرسمية ضامنة للجديد.
  • نفس الآلية تعمل لكل القنوات الـ21 (وادي الذئاب، WWE، الجزيرة الوثائقية، سبيستون…).
  • لماذا لا نعتمد بروكسيًا عامًا؟ اختبرنا 12 بروكسيًا (allorigins، codetabs، corsproxy، jina، thingproxy…) — كلها ميتة أو مقيدة أو ترفض IP مراكز البيانات في 2025، لذلك الحل الرسمي هو الأساس.

8تجربة الهاتف (الأولوية الأولى)

  • ثبات المشغل: عند التمرير داخل المكتبات يثبت المشغل أسفل الترويسة ويصغر تلقائيًا (IntersectionObserver) — المشاهدة والتنقل معًا دون إعاقة المحتوى. مُثبت بلقطة حية على عرض 390px.
  • نفس تعديلات Live TV v2.4.0: «التالية» أولًا بصريًا (order:-1) بنص مختصر، وشبكة عمودين على الشاشات الصغيرة.
  • ورقة تفاصيل سفلية (Bottom Sheet) بحد آمن iOS، أهداف لمس ≥44px، شريط حلقات قابل للتمرير أفقيًا، تذييل يلتصق بالأسفل ويُدفع طبيعيًا مع طول المحتوى.
  • عند اختيار حلقة من قائمة بعيدة تعود الشاشة تلقائيًا إلى المشغل.
